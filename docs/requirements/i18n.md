# I18N requirements

Localization rules. Implemented with Paraglide JS. Source of truth is
`.verorules/instructions.md` and `src/hooks.ts`.

### REQ-I18N-001 - Czech default, English prefixed

- Status: verified
- Priority: must
- Source: instructions
- Description: Czech is the default locale served without a URL prefix; English is served under an `/en` prefix.
- Acceptance:
  - Given the site
  - When a Czech URL is visited, it has no locale prefix (e.g. `/produkty`)
  - When the English equivalent is visited, it is prefixed with `/en` (e.g. `/en/produkty`)
- Test: tests/e2e/i18n.spec.ts > REQ-I18N-001

### REQ-I18N-002 - All copy via message functions in both locales

- Status: verified
- Priority: must
- Source: instructions
- Description: All user-facing copy comes from Paraglide message functions, with every key defined in both `messages/cs.json` and `messages/en.json`.
- Acceptance:
  - Given a page with user-facing text
  - When it renders
  - Then no hardcoded copy is used, and every message key exists in both cs.json and en.json
- Test: tests/e2e/i18n.spec.ts > REQ-I18N-002

### REQ-I18N-003 - Internal links respect the active locale

- Status: verified
- Priority: must
- Source: instructions
- Description: Internal links are localized so they keep the active locale.
- Acceptance:
  - Given a page rendered in English
  - When it shows an internal link
  - Then the link points to the `/en`-prefixed URL (via localizeHref)
- Test: tests/e2e/i18n.spec.ts > REQ-I18N-003

### REQ-I18N-004 - Every route prerenders in both locales

- Status: verified
- Priority: should
- Source: TODO
- Description: Every route is prerendered for both the Czech and English locales.
- Acceptance:
  - Given the production build
  - When prerendering completes
  - Then each route exists as a prerendered page under both the root (cs) and `/en` (en) paths
- Test: tests/e2e/i18n.spec.ts > REQ-I18N-004
